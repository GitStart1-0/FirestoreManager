# Специфікація Структури Бази Даних Noesis (Firestore Schema)

Цей документ містить повний опис структури бази даних **Firestore**, яка використовується конструктором Noesis для збереження категорій, рівнів та всіх 13 типів питань. Він створений для того, щоб ви могли легко змонтувати та інтегрувати отримання даних у вашому окремому мобільному або веб-застосунку.

---

## 1. Головна Архітектура & Два Варіанти Збереження

Конструктор записує питання у **два формати одночасно**, щоб ви могли вибрати найзручніший спосіб завантаження у вашому застосунку:

### Варіант А: Вкладена Карта (Nested Map) всередині документу Рівня (Рекомендовано для швидкого завантаження)
Всі питання рівня зберігаються безпосередньо в основному документі рівня під полем `questions`, яке є картою (Map/Dictionary). 
* **Шлях до документу**: `/{назва_категорії}/{номер_рівня}` (наприклад, `/erudite/1`)
* **Перевага**: Одним запитом до документу рівня ви отримуєте метадані рівня (автор, назва, опис) разом із **усіма** питаннями цього рівня. Не потрібно робити додаткові запити до підколекцій, що значно економить квоти читання (NoSQL Read Costs).

### Варіант Б: Окрема Підколекція (Subcollection) Питань
Кожне питання записується як окремий документ у підколекцію `questions` під документом рівня.
* **Шлях до коллекції**: `/{назва_категорії}/{номер_рівня}/questions` (наприклад, `/erudite/1/questions`)
* **Перевага**: Зручно, якщо Питання містять занадто багато великих даних і ви хочете завантажувати їх сторінками (Pagination/Streams).

## ⚠️ Чому ваш застосунок може не отримувати питання з БД?

Якщо ваш застосунок отримує метадані рівнів (кількість, назву), але не бачить питань, причина зазвичай полягає в одному з наступних факторів:

1. **Неглибокі запити Firestore (Shallow Queries)**:
   Якщо ви робите запит типу `db.collection("erudite").get()`, Firestore завантажує лише документи у цій колекції (рівні з їхніми полями). **Він ніколи автоматично не завантажує документи з підколекцій** (таких як `.../1/questions/...`). Для завантаження з підколекції ви маєте зробити окремий запит:
   ```kotlin
   // Приклад на Kotlin (Android)
   db.collection("erudite").document("1").collection("questions").get()
   ```
2. **Відсутність мапінгу поля `questions` у моделі даних**:
   Якщо ви намагаєтесь прочитати питання з вкладеної карти самого документу рівня, переконайтеся, що ваша модель даних (Data Class / Struct) містить поле `questions: Map<String, Question>` або аналогічне, і ви правильно його десеріалізуєте.
3. **Правила безпеки (Security Rules)**:
   Переконайтеся, що правила безпеки для вкладеної підколекції дозволяють читання:
   ```javascript
   match /{category}/{levelDoc} {
     allow read: if true;
     match /questions/{questionDoc} {
       allow read: if true; // Дозволити читання підколекції
     }
   }
   ```

## 2. Повна Специфікація Моделей Даних

### А. Основний документ Рівня (Level Document)
* **Колекція (Батьківська)**: `/{category}` (наприклад: `erudite`, `philosophy` тощо)
* **ID Документу**: `1`, `2`, `3` ... (строкове представлення номеру рівня)

#### Поля документу:
| Назва поля | Тип даних | Опис | Приклад значення |
| :--- | :--- | :--- | :--- |
| `levelNumber` | Number | Порядковий номер рівня | `1` |
| `name` | String (Опціонально) | Назва або назва квізу | `"Вступ до філософії"` |
| `author` | String (Опціонально) | Автор рівня | `"Noesis AI"` |
| `description` | String (Опціонально) | Опис теми або завдання | `"Основи логіки, деонтології та історії світової думки."` |
| `subscriptionTier` | String | Доступний тир підписки | `"free"`, `"plus"`, `"expert"` |
| `status` | String | Статус доступності рівня за замовчуванням | `"UNLOCKED"` |
| `questionCount` | Number | Кількість записаних питань на рівні | `5` |
| `questions` | Map | Карта всіх питань, де ключ - це ID питання, а значення - об'єкт питання (див. нижче) | `{ "ua--01--A--utilitarianism...": { ... } }` |

---

### Б. Спільні поля для всіх Типів Питань (Base Question Fields)
Кожне питання (чи всередині карти `questions`, чи в колекції `/questions/`) має базовий набір універсальних полів:

| Назва поля | Тип даних | Опис | Приклад значення |
| :--- | :--- | :--- | :--- |
| `lang` | String | Мова питання | `"ua"`, `"en"` |
| `type` | String | Конкретний тип питання (один з 13) | `"SINGLE_CHOICE"`, `"MATCHING"`, `"PAIRWISE_DISTINCTION"`... |
| `question` | String | Головний текст питання (крім типів `READING_COMPREHENSION` та `PAIRWISE_DISTINCTION`) | `"Який основний принцип утилітаризму?"` |
| `topics` | Array of Strings | Список тегів теми | `["етика", "утилітаризм"]` |
| `scientificDisciplines` | Array of Strings | Масив наукових дисциплін за класифікатором | `["philosophy"]` |
| `explanation` | String | Детальне пояснення правильної відповіді | `"Бентамова етика оцінює дію за її наслідками..."` |
| `recommendedLiterature` | Array of Objects | Список літератури/посилань | `[{"name": "Вступ до принципів моралі", "link": "https://..."}]` |
| `literatureHiddenAtStart` | Boolean | Чи прихована рекомендована література до надання відповіді | `true` або `false` |

## 3. Схеми Опцій та Відповідей для кожного з 13 Типів Питань

Усі 13 типів питань мають ідентичні спільні базові поля (`lang`, `type`, `topics`, `scientificDisciplines`, `explanation`, `recommendedLiterature`, `literatureHiddenAtStart`). Нижче наведено специфічні поля структури даних, які додаються залежно від типу (`type`).

### 1) SINGLE_CHOICE (Один правильний варіант)
* **Опис**: Стандартне питання з декількома варіантами вибору, серед яких правильний лише один.
```json
{
  "answers": [
    "Максимізація найбільшого щастя для найбільшої кількості людей",
    "Дотримання морального обов'язку",
    "Пошук істини через діалог"
  ],
  "correctAnswerIndices": [0]
}
```

### 2) MULTIPLE_CHOICE (Кілька правильних варіантів)
* **Опис**: Користувач може обрати кілька правильних відповідей.
```json
{
  "answers": [
    "Утилітаризм оцінює наслідки дій",
    "Засновником вважається Джеремі Бентам",
    "Він виключає поняття щастя з етики"
  ],
  "correctAnswerIndices": [0, 1]
}
```

### 3) TRUE_FALSE (Правда / Брехня)
* **Опис**: Твердження, з яким гравець погоджується або ні. Список `answers` відсутній.
```json
{
  "correctAnswer": false
}
```

### 4) SEQUENCE (Хронологічна / Логічна послідовність)
* **Опис**: Гравець має розташувати пункти за порядком. `answers` містить елементи в довільному порядку, а `correctAnswerIndices` вказує правильний індекс послідовності (від 0 до N).
```json
{
  "answers": [
    "Хрещення Русі",
    "Заснування Києва",
    "Люблинська унія",
    "Проголошення Незалежності"
  ],
  "correctAnswerIndices": [1, 0, 2, 3] 
}
// Правильний порядок: Заснування Києва (1), Хрещення Русі (0), Люблинська унія (2), Незалежність (3)
```

### 5) MATCHING (Встановлення відповідності між колонками)
* **Опис**: Гравець з'єднує ліву колонку (Left Side) з правою колонкою (Right Side).
* `correctMatches` містить зв'язок `leftIndex` (від 0 до N) з `rightIndex` (від 0 до M). Права колонка може мати дистрактор (відволікаючий пустий елемент).
```json
{
  "leftSide": [
    "Кант",
    "Бентам",
    "Епікур"
  ],
  "rightSide": [
    "Категоричний імператив",
    "Принцип користі",
    "Епікурейство",
    "Діалектичний матеріалізм" // Зайвий дистрактор
  ],
  "correctMatches": [
    { "leftIndex": 0, "rightIndex": 0 },
    { "leftIndex": 1, "rightIndex": 1 },
    { "leftIndex": 2, "rightIndex": 2 }
  ]
}
```

### 6) COMPARISON (Порівняльна таблиця / Діаграма Венна)
* **Опис**: Твердження розподіляються по 2 окремим філософським категоріям або у спільну зону ("Спільне").
```json
{
  "categories": ["Емпіризм", "Раціоналізм", "Спільне"],
  "statements": [
    {
      "text": "Наголошує на ролі чуттєвого досвіду",
      "correctCategory": 0
    },
    {
      "text": "Наголошує на ролі логічного мислення",
      "correctCategory": 1
    },
    {
      "text": "Класичні розділи теорії пізнання (гносеології)",
      "correctCategory": 2
    }
  ]
}
```

### 7) TEXT_INPUT (Введення текстової відповіді з клавіатури)
* **Опис**: Користувач власноруч пише термін у текстове поле.
```json
{
  "correctAnswers": ["утилітаризм", "utilitarianism"]
}
```

### 8) FILL_IN_THE_BLANK (Заповнення пропусків)
* **Опис**: Текст з пропущеними словами. В полі `question` зберігається повний текст, де пропущені місця позначені як ` [ ] `. Поле `correctAnswers` містить масив правильних слів для пропусків по черзі.
```json
{
  "question": "Етична теорія Бентама називається  [ ] , а теорія Канта в основі містить  [ ]  імператив.",
  "correctAnswers": [
    "утилітаризм",
    "категоричний"
  ]
}
```

### 9) IMAGE_CHOICE (Оцінка картинки чи вибір візуального зображення)
* **Опис**: Питання, де варіанти відповідей (`answers`) представлені у вигляді HTTP URLs на зображення.
```json
{
  "answers": [
    "https://images.unsplash.com/photo-1546182990-dffeafbe841d?w=400",
    "https://images.unsplash.com/photo-1595152772835-219674b2a8a6?w=400"
  ],
  "correctAnswerIndices": [1]
}
```

### 10) READING_COMPREHENSION (Текстове дослідження з підпитаннями)
* **Опис**: Складний кейс-рівень. Користувачу дається один або два великих уривки тексту (`text1`, `text2`), а до них прив'язано кілька підпитань з власною структурою.
* **Зверніть увагу**: загальне поле `question` у цьому типі **відсутнє (deleted)**.
```json
{
  "text1": "Наші вчинки мають утилітарну цінність. Чим більше загальної користі ми приносимо...",
  "text2": "Проте кантіанська деонтологія наполягає на зворотному: наслідки ніщо...",
  "questions": [
    {
      "question": "Що є головним критерієм моральності за Бентамом?",
      "options": [
        "Загальна користь результату",
        "Суворий моральний обов’язок",
        "Релігійні канони"
      ],
      "correctAnswerIndex": 0
    },
    {
      "question": "Чому деонтологія протилежна утилітаризму?",
      "options": [
        "Вона ігнорує наслідки вчинків",
        "Вона підтримує матеріальну вигоду"
      ],
      "correctAnswerIndex": 0
    }
  ]
}
```

### 11) SLIDER_SCALE (Встановлення значень на шкалі / Слайдер від 0 до 100)
* **Опис**: Гравець виставляє правильний відсоток чи числове значення на слайдері.
```json
{
  "text": "У соціологічному дослідженні соціо-етики визначався рівень підтримки респондентів.",
  "sliders": [
    {
      "question": "Який відсоток опитаних повністю відкинули деонтологію?",
      "correctAnswer": 42
    },
    {
      "question": "Скільки підтримали альтернативну версію?",
      "correctAnswer": 78
    }
  ]
}
```

### 12) TEN_FACTS (Гра "10 фактів про сутність" / Синопсис)
* **Опис**: Гравець бачить 10 фактів про відому людину/явище та має обрати її ім'я зі списку варіантів (`answers`), на користь правильного індексу (`correctAnswerIndices`).
```json
{
  "facts": [
    "Він народився в Лондоні у родині юристів.",
    "Вивчав латину у віці трьох років.",
    "Заповідав забальзамувати своє тіло після смерті."
  ],
  "answers": [
    "Джеремі Бентам",
    "Іммануїл Кант",
    "Джон Локк"
  ],
  "correctAnswerIndices": [0]
}
```

### 13) PAIRWISE_DISTINCTION (Розрізнення та класифікація між двома об'єктами)
* **Опис**: Гравець порівнює два близькі об'єкти (наприклад, *Алігатор* та *Крокодил*) за завантаженими зображеннями та підписами і розподіляє масив характеристик/тверджень (`statements`) між цими двома об'єктами.
* **Особливість**: Загальне поле `question` у цьому типі **відсутнє (deleted)**, оскільки формулювання запитання генерується клієнтським додатком нативно (наприклад: *"Яка різниця між {Name1} та {Name2}?"*).
```json

  "objects": [
    {
      "id": "alligator",
      "name": "Алігатор",
      "imagePath": "/quiz-images/erudite/level-0001/q012/alligator.webp",

    },
    {

      "altText": "Голова крокодила з вузькою мордою"
    }
  ],
  "statements": [
    {
      "id": "snout_u",
      "text": "Має широку U-подібну морду",
      "correctObjectId": "alligator"
    },
    {
      "id": "snout_v",
      "text": "Має вужчу V-подібну морду",

    {
```

## 4. Приклади інтеграції та зчитування у вашому мобільному застосунку

### Варіант А: Зчитування вкладених питань (Kotlin для Android)

Якщо ви використовуєте **вкладений Map**, ви можете зчитати весь рівень і розпарсити питання за один запит:

```kotlin
import com.google.firebase.firestore.FirebaseFirestore

data class Level(
    val levelNumber: Int = 0,
    val name: String = "",
    val author: String = "",
    val description: String = "",
    val questionCount: Int = 0,
    val subscriptionTier: String = "free",
    val questions: Map<String, Map<String, Any>> = emptyMap() // Мапа з питаннями!
)

fun fetchLevelWithNestedQuestions(category: String, levelId: String) {
    val db = FirebaseFirestore.getInstance()
    
    db.collection(category).document(levelId)
        .get()
        .addOnSuccessListener { documentSnapshot ->
            if (documentSnapshot.exists()) {
                val level = documentSnapshot.toObject(Level::class.java)
                println("Рівень: ${level?.name}, Кількість питань: ${level?.questionCount}")
                
                // Проходимо по мапі питань
                level?.questions?.forEach { (questionId, questionMap) ->
                    val type = questionMap["type"] as? String
                    val questionText = questionMap["question"] as? String
                    println("Питання [$questionId] типу ($type): $questionText")
                }
            } else {
                println("Рівень не існує!")
            }
        }
        .addOnFailureListener { exception ->
            println("Помилка завантаження: ${exception.message}")
        }
}
```

### Варіант Б: Завантаження через підколекцію `/questions` (Flutter / Dart)

Якщо ви бажаєте робити запити до **підколекції**:

```dart
import 'package:cloud_firestore/cloud_firestore.dart';

Future<void> fetchQuestionsFromSubcollection(String category, String levelId) async {
  try {
    var collectionRef = FirebaseFirestore.instance
        .collection(category)
        .doc(levelId)
        .collection('questions');

    var querySnapshot = await collectionRef.get();
    
    print('Знайдено окремих питань у підколекції: ${querySnapshot.docs.length}');
    
    for (var doc in querySnapshot.docs) {
      var data = doc.data();
      print('ID Питання: ${doc.id}');
      print('Тип поля: ${data['type']}');
      print('Текст питання: ${data['question']}');
      print('---');
    }
  } catch (e) {
    print("Помилка завантаження підколекції: $e");
  }
}
```

## 5. Додатковий інструмент у конструкторі: "Авто-запуск Рівня 1"

Для полегшення перевірки та тестування, ми додали кнопку **"Авто-запуск Рівня 1" (Quick Seed Level 1)** безпосередньо в конструктор (поруч із кнопкою збереження). 
Вона автоматично створює в базі даних категорію `erudite`, створює `Рівень 1`, наповнює його метаданими та автоматично генерує **5 повноцінних демонстраційних питань** різних типів (одновибірний, правда/брехня, відповідність, хронологія, текстове введення), записуючи їх **як у вкладену карту, так і в підколекцію**.

Ви можете натиснути цю кнопку, обрати в провіднику Експлорера (таб Explorer) колекцію `erudite` та документ `1`, щоб наочно перевірити структуру та порівняти її з кодом вашого застосунку!
